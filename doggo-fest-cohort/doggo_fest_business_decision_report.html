④ 下次分析：要加什麼 tag / 追蹤才收錄得更完整

底線：想把 204 名新客／回流客也納入因果分析，關鍵不是收多些人，而是在活動前就為他們留下可配對的 baseline（pet tag、渠道、signup）；否則他們永遠只能做描述性 benchmark。

放寬配對方法改 1:3、nearest-neighbor / PSM（用可觀察 covariates 而非 pre 行為）+ caliper，讓新客也能配對。
擴大 control 池不限 Typical Pet 3,470，擴到全 HK existing pet，替 32 名落空既有客找同桶對象。
Voucher attribution記錄「已派 vs 已用」，連未兌換者都能追蹤，treatment 不只靠活動窗兌換。
結構化 pet / service tag目前 BQ 無乾淨 pet 欄（靠 request_remarks，noise 大）；有 tag 才能識別活動窗外的 pet 行為，建立 pre-window baseline。
新客 signup + 渠道寫入 signup date 與獲取渠道，讓新客可用 observed-covariate 配對，而非只做 benchmark。
Direction / venue tag 入 BQ目前只靠 Sheet tst_496（覆蓋 122/140），入 BQ 才完整。
分渠道成本明細不只 Sheet grand total，讓 ROI proxy 做得更準。
⑤ 為何唔把 Pre window 拉長到 365 日？
結論：不建議把活動前觀察窗由 180 日拉長到 365 日。拉長 Pre window 不會增加實驗組人數——Doggo Fest 實驗組由 voucher 使用定義，仍是 372 人；改窗只影響「多少人能找到相似對照組」，不改變誰是參加者。而且 365 日只救到部分回流客，救不到真新客，還會破壞 Pre／Post 對稱，令 DiD 較難解讀。

會影響哪些人？

分段拉到 365 日有冇幫助原因
真新客 102 人無幫助生涯首單就在活動期；即使 Pre 拉到 365 日，活動前仍沒有歷史訂單，不能用活動前行為配對。
回流客約 100 人部分有幫助若上次下單在活動前 180–365 日之間，365 日窗可重新看到舊紀錄；但只代表他曾用過，不代表近期活躍。
既有客 32 人無幫助問題不是沒有歷史，而是 control pool 找不到夠相似的對照；要擴大 control pool，而非拉長 Pre window。

1. Pre／Post 必須對稱，否則 DiD 有偏差

本分析用活動前 180 日、活動後 180 日，兩段等長，Post−Pre 可直接解讀。若改成 Pre = 365 日、Post = 180 日，Pre 期自然累積更多訂單／GTV／platform_take（時間接近 Post 的兩倍），會令 Post−Pre 被人為拉低、DiD 結果不公平。若一定要用 365 日 Pre，就不能用累計值直接比較，必須改成人均每日率（每人每日訂單／GTV／platform_take）；但這樣整個 KPI 定義會改變，不能與目前 180／180 的結果直接混用。

2. 回流客本質是 Reactivation，不應與既有活躍客混在一起

一個客戶 250 日前下過單、最近 180 日完全沒用，他在活動前最近 180 日並非活躍用戶；拉到 365 日看到舊單也不改變這事實。這類客戶應獨立分析為 reactivation / win-back，而非與 existing active 的增量混合。

客群要回答的商業問題
Existing active對近期本來已活躍的寵物客，Doggo Fest 有沒有帶來額外增量？
ReactivatedDoggo Fest 有沒有把休眠客叫回來？

這是兩個不同的商業問題，不應用同一 headline 混合解讀。

3. 樣本變多，不代表結論更可信

目前 mixed matched DiD 為 140 對，統計信心已有限（CI 含 0）。若把更多行為不穩定的回流客加入，樣本數會增加，但變異也增加，信賴區間可能更闊。更多人 ≠ 更可信——應優先保留乾淨、可解讀的 matched sample，而非為了衝樣本數把行為差異很大的客群混在一起。

正確做法（按客群改方法，而非拉長窗）

目標建議做法
分析真新客不用 DiD；改用 signup date、渠道、地區、首單特徵、device 等 observed covariates 做 PSM / matching，或用同期 organic 新客做 benchmark。
分析回流客獨立做 reactivation analysis，不與 existing active 混合。
增加既有客 matched sample擴大 control pool，為未配對的既有客尋找更多相似對照。
一定要用 365 日 PreKPI 改成人均每日率，避免 365 日累計值與 180 日累計值直接比較。
對外解讀：拉長 Pre window 到 365 日不能解決全部配對問題——只幫到部分回流客，幫不到真新客；且若 Post 仍是 180 日，Pre／Post 長度不一致會令 DiD 有偏差。因此本報告保留 180／180 對稱時間窗，重點放在可乾淨配對的 matched sample；未來要提高覆蓋率，正確方向是改進配對方法與擴大 control pool，而非單純加長 baseline window。

活動真有增量：扣除對照組後 orders / GTV / platform_take 仍為正

活動不是只有「參加者 post 有收入」，而是扣除對照組後，訂單、GTV、platform_take 仍然有正增量。以下皆為人均（/ 人），不是 per order、也不是全體加總；pre / post 各 180 天（活動日 2025-11-14 至 11-16 不計）。

解讀：每人先算 pre 180 天與 post 180 天的差（Post−Pre），再比實驗組與對照組的平均變化差距（DiD）。+1.34 單/人 = 每人 post 期比 pre 期平均多完成 1.34 張單，不是「每張單」的增量。樣本：140 對 matched users。

既有活躍客有正增量：HK$89.72 / 人

7. 如果無做 Doggo Fest，結果會點？

用 matched control 作為「無活動代理」；將實際 post 180 日結果與 no-event counterfactual 比較。不是 forecast model。

Doggo Fest 的價值不是「post 有收入」，而是「實際 post 比無活動預期多了多少」——人均活動增量 +HK$25.37（140 對 matched users）。
