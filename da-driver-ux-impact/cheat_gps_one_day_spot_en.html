1) GPS jumps too fast — two neighbouring rows

More ▾

In Admin Trip History, each row is one GPS ping (time + lat + lon). We only compare this row to the row right under it. Time gap is usually about 1 minute when the clock shows 19:08 then 19:09 (not 1 second). Distance ÷ time = speed. If speed ≥ 100 km/h, we mark a red line on the map.

Same ~1 minute on both sides. Distance: ~350 m vs ~6 km. That is why one is OK (~21 km/h) and one is a red line (~360 km/h).

Method notes

Stitch: Admin shows GPS per order request → list day’s orders from BQ order_master_table_hk → concat pings → sort by timestamp → spot on one map.
GPS source (this pilot): Admin Trip History style fixtures (stitched by order_request_id). Bulk analytics_db.driver_location* not readable under current IAM.
Order source: gogox-data-science-non-prod.analytics_prod_master.order_master_table_hk （2026-08-03 實查，HK TRANSPORT，driver-days 2026-07-10 / Admin 2026-06-04）
Method: Spot only (no score) — Rule-based only (GPS jumps too fast / back and forth in a tiny area / stuck vs far order). No ML model.
Packages: pandas-ready CSV · folium maps · rules in python/cheat_gps/rules.py.
