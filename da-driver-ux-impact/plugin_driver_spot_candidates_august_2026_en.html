How we count (read this once)

Expand ▾
OA orders left out — An order with event_type_cd = 26 is left out. The whole order is out. OA drivers stay.
Picked — any of event_type_cd 2, 20 (the driver pressed to pick it), or 22 (driving mode). The 6,275 are drivers who picked.
Assigned — only event_type_cd 2 (orders_assigned_30d). Not the same as picked. One driver and one order count once. Release rate uses this number, not the picked count.
Release rate (scoring) — releases ÷ assigned (releases_by_driver_30d ÷ orders_assigned_30d). Not completed + cancelled.
Cancel rate (scoring) — driver cancel ÷ (completed + driver cancel) = driver_cancel_30d ÷ (orders_completed_30d + driver_cancel_30d). Driver cancel = event_type_cd = 3 + actor_type = 'Driver'. Different base from Release — do not mix them.
Released vs driver cancel — Released = the driver had the order, then released it back to the pool (event_type_cd = 4, actor_type = 'Driver'). Driver cancel (used in Cancel rate) = driver cancelled the order (event_type_cd = 3, actor_type = 'Driver'). Release returns the order to the pool; cancel ends the order. Pool entry does not require a release.
Who gets a score — they picked an order (event_type_cd 2, 20, or 22). OA orders (event_type_cd = 26) are left out. OA drivers stay. Assigned ≥30 and completed ≥30 are not required.
Bot pool — 2+ different grace-drops (grabbed then let go fast, event_type_cd = 21) in the same 3 seconds (is_bot_pool_v2). Review bands = Extreme case (not scored) + Assigned (0–2) + Release (0–4) + Cancel (0–2) → max 8.
How to read filters — Figure 1 (①–④) = mart totals, broken down by Booking × Vehicle × Membership. All three filters are unique-driver splits of the same cards (6,282 / 6,275 / 210 / 20). Booking = each driver’s primary booking type (most assigned in August; tie → On Demand). OD + SD + ND must add up to All — same idea as Vehicle / Membership.
