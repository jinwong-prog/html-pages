How we count (read this once)

Expand ▾
OA excluded — Auto-accept (OA) orders and OA drivers are out of this page — via event_type_cd = 26.
Release rate (scoring) — releases ÷ assigned (releases_by_driver_30d ÷ orders_assigned_30d). Not completed + cancelled.
Cancel rate (scoring) — driver cancel ÷ (completed + driver cancel) = driver_cancel_30d ÷ (orders_completed_30d + driver_cancel_30d). Driver cancel = event_type_cd = 3 + actor_type = 'Driver'. Different base from Release — do not mix them.
Released vs driver cancel — Released = driver took the order then released it back to the pool (event_type_cd = 4, actor_type = 'Driver'). Driver cancel (used in Cancel rate) = driver cancelled the order (event_type_cd = 3, actor_type = 'Driver'). Release returns the order to the pool; cancel ends the order. Pool entry does not require a release.
Who gets a score — in this 30d: must took ≥30 orders (orders_assigned_30d), finished ≥30 (orders_completed_30d), not OA. If any rule fails → outside_analysis_pool (not scored yet; can still work).
Bot pool — 2+ different grace-drops (grabbed then let go fast, event_type_cd = 21) in the same 3 seconds (is_bot_pool_v2). Review bands = Extreme case (not scored) + Assigned (0–2) + Release (0–4) + Cancel (0–2) → max 8.
How to read filters — Figure 1 (①–④) = driver totals. Vehicle / Membership break down the 134 bot drivers (and the checked/working universe): van + mudou + mudou9 = 134; membership tiers = 134. Booking breaks down released orders among those bots (On Demand / Same Day / Next Day %); each order once; sums to 100% — not 134 people. Booking does not change ①–④.
